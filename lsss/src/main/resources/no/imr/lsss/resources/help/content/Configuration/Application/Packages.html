Packages configuration

Packages define a way to extend LSSS with custom functionality, such as callbacks, keystrokes, toolbar buttons, and menus.

These custom user interface elements are associated with actions, which are Python scripts using the HTTP API of the LSSS server. The Python scrips make use of the requests Python library, so make sure it is available in the configured Python executable.

Packages

A package must have a unique ID and is stored in a directory with the following structure: 

   - {package ID}         // Directory for this package
      - package-info.json // Configuration of this package
      - actions           // Directory with all actions in this package
         - {action ID}    // Directory for an action
            - info.json   // Configuration of this action
            - main.py     // The Python script executed by the action
         - ...            // More action directories
      - doc               // Optional directory with documentation of this package
         - index.html     // The main entry point for the package documentation

LSSS has a bundled example package that can be installed via the button located to the right of the "Packages" header.

Actions

An action must have a unique ID within its package.

The Python code associated with an action is stored in the file main.py. The main.py file contains a header generated by LSSS that imports the library lsss.py. The lsss.py library is common for all actions in all packages and contains functions for using the HTTP API of the LSSS server.

An action consists of the following:

  • ID: The unique ID within its package.
  • Label: Optional label.
  • Tooltip: Optional tooltip.
  • Icon: Optional icon in SVG format.
  • Inputs: Optional input parameters for this action. If input parameters are specified, then LSSS shows an input dialog before executing the action. The values of the input parameters are made available to the action script via the lsss.py library.
  • Show dialog: Whether LSSS should show a dialog if the action execution takes more than a brief moment.
  • main.py: File containing Python code.

The lsss.py library

This library is included by the automatically generated header of the Python action script. The library provides:

  • baseUrl is a string of the form http://127.0.0.1:serverPort, where serverPort is the actual port number configured in LSSS. The baseUrl variable is normally not needed directly.
  • get, post and delete are functions that wrap requests to the LSSS server using the requests Python library. These functions check for error and convert the response body to a Python object. If the response status code indicates an error, then an exception is raised.
  • input is a dictionary from name to value for the configured input parameters.

Examples:

  • Get the current zoom of the pelagic echogram:
    zoom = lsss.get('/lsss/module/PelagicEchogramModule/zoom')
  • Select the "Combined" colormap:
    lsss.post('/lsss/module/ColorBarModule/colormap', json={'value': 'Combined'})
  • Get the value of an input parameter named depth:
    depth = lsss.input['depth']

Callbacks

A package can define callbacks that execute actions at various events in LSSS.

Event Description
applicationExit Immediately before LSSS is going to shut down.
applicationStart Immediately after LSSS has started.
surveyClose After a survey has been closed.
surveyOpen After a survey has been opened.

If there are several callbacks for the same event, then all actions are executed. The execution order of multiple actions is not specified.

Keystrokes

A package can define mappings from keystrokes to actions. The action will only be executed if the selected context has keyboard focus.

Context Keyboard focus
Anywhere The keyboard focus can be anywhere.
AnyEchogramModule The keyboard focus must be in the pelagic or the bottom echogram module.
MainWindow The keyboard focus must be in the main LSSS window, not in any associated windows or dialogs.
The name of a view module The keyboard focus must be in that module.

If there are several mappings applicable for a keystroke, then all actions are executed. The execution order of multiple actions is not specified.

Toolbar buttons

A package can define custom toolbar buttons that will be placed to the right of the standard buttons in the toolbar. Each toolbar button is associated with an action that will be executed when clicking the button.

The order of the toolbar buttons can be changed by dragging with the mouse.

Menus

A package can define custom menus that will be placed to the right of the standard menus in the menu bar. Each menu item is associated with an action that will be executed when selecting the menu item.

The order of menus, submenus, and menu items can be changed by dragging with the mouse.
