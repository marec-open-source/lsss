Database LSSS

The database contains the results of the scrutinizing of the acoustic data and some information needed during the scrutinizing process. The communication with the relational database is done through Hibernate and JDBC. Several database engines may be used, including:

  • HSQLDB - Requires no server. Stored in files, text or binary. This database may not be suitable for large databases.
  • JavaDB - Requires no server. Stored in binary files.
  • PostgreSQL

The figure below shows how the database tables relate to each other. Some tables keep general information about the data, i.e. name and code of nations, observing platforms and surveys. Some tables keep information about the observations itself, i.e. about the data-stations and its belonging navigation data and comments. Some tables keep the data from the data-stations, e.g. the acoustic data. Some tables keep the information about the biological species and acoustic categories.

The database tables in alphabetic order are as follows (tables in red are implemented, but not fully used):

  • AcCatToBiologicalSpecies - Coupling between acoustic category and biological species
  • AcousticCategory - Acoustic category, i.e. "acoustic species" used during data interpretation
  • AcousticCategoryComposite - Acoustic category composed by several non-composite acoustic categories
  • Area - Name of sea areas
  • AreaOfAcousticCategory - Coupling between acoustic category and area
  • BiologicalSpecies - Names and codes of biological species
  • Nation - Name and code of nation
  • Observation - Observation and its coordinates
  • ObservationComment - Observation comments
  • ObservationType - Observation type
  • Personnel - personnel and duty on survey
  • Platform - Observing platform (e.g. ship or buoy)
  • PlatformCodes - Platform codes in alternative coding systems
  • PlatformName - Platform names
  • PlatformType - Name of platform types and subtypes
  • Purpose - Purpose of using acoustic category in the scrutinizing process
  • Scatter - Main scatter information
  • ScatterData - Depth-channel data of acoustic scatter
  • ScatterObject - Group of scatter (e.g. entire school)
  • ScatterType - Type of scatter-channels
  • SchoolCategory - Acoustic category for school object
  • SchoolCategorySystem - Code system for school
  • SchoolData - Data for school object (in addition to Scatter)
  • SchoolDetect - Settings used to detect school
  • SchoolMorphology - Morphology of school
  • SchoolObjectType - Type of school object
  • StandardComment - Frequently used observation comments
  • Survey - Survey information

About the fields in the database tables

The size of the fields of each table is given as short, int, long, char or float. The sizes of each of these fields are as follows: 

  short:  2 byte (int 2)
  int:    4 byte (int 4)
  long:   4 byte (int 4)
  char:   1 byte (int 1)
  float:  4 byte (float 4)
  double: 8 byte (float 8)

The fields Date and Time (ObservationDate, StartDate, ObservationTime, StartTime, ...)

  • Date format - YYYYMMDD where YYYY is year, MM is month, DD is day.
  • Time format - hhmmssxx where hh is hour, mm is minutes, ss seconds, xx 1/100 of seconds
