Description

Interpreted echo data from scattered fish are stored in the tables Scatter and ScatterData. The data are stored in the tables with a selectable horizontal resolution. The database table Scatter contains processing and support parameters. The database table ScatterData contains the integrated echo levels in depth-channels as sA (Nautical Area Scattering Coefficient). Vertically, the data in Scatter and ScatterData tables are resolved into depth-channels; pelagic and bottom. The ScatterType parameter determines if the scatter data are taken from pelagic or bottom channels, while channel thickness is controlled by the ChannelThickness parameter. When stored to the database, there will for each subinterval be stored: one ObservationType = "Scattered Fish Data" event line is added to the ObservationType table, one line is added to the Scatter table several lines are added to the ScatterData table.

Parameters

  • Nation - [-] Unique nation identification code. Refer to the Nation database table.
  • Platform - [-] Unique platform (vessel) identification code. Refer to the Platform database table.
  • Survey - [-] Unique survey identification code. See the Survey table.
  • Object - [-] Object identification number. The number is used to group scattered data. The primary gain is thought to be by using the Object number to group scattered data from schools. The Object (number) is shared between the frequencies. There are currently two types of objects that are numbered: echogram and school. Each of these two object-types have surface-referenced depth-channels (scatter-type Echogram-Pelagic or School-Pelagic of the ScatterType database table), and may in addition also have bottom-referenced depth-channels (scatter-type Echogram-Bottom or School-Bottom of the ScatterType database table) if BottomActive = TRUE (see below).
    For School: each of the regions of acoustic data (at all frequencies) in the section visible on the computer-display scrutinized as a single school is given the same Object (number) when stored to the database.
    For Echogram: all acoustic data (at all frequencies) in the section visible on the computer-display is given the same Object number when stored to the database if stored in the same store-operation. If the echograms at different frequencies are NOT stored in the same operation, the echograms will be given different Object number. Note that if a section of the echogram-object is deleted at a later stage, the same section is deleted at all frequencies simultaneously, and the remaining undeleted section will keep the original Object number. Further, if the deleted section is re-scrutinized and stored to the database again, the new section stored to the database will be given a different Object number than the original.
  • ObservationDate - [YYYYMMDD] (UTC) Each line in the Scatter table is time stamped with the start of the associated subinterval, and there is a "Scattered Fish Data" event line in the ObservationType table with a matching time stamp.
  • ObservationTime - [hhmmssxx] (UTC) Each line in the Scatter table is time stamped with the start of the associated subinterval, and there is a Scattered Fish Data event line in the ObservationType table with a matching time stamp.
  • Frequency - [Hz] Echosounder operating frequency in Hz.
  • Transceiver - {1; ...} Echosounder transceiver or GPT channel number.
  • ScatterType - {...} Type of scatter data. See the ScatterType database table.
  • ObservationType - {...} Type of observation. See the ObservationType table.
  • Duration - [1/100 s] This parameter states the duration in hundredths of seconds (1/100) for the current subinterval.
  • DistanceInterval - [nmi] This parameter states the distance in nautical miles (1 nmi = 1852 m) covered by the current subinterval.
  • MinBottomDepth - [m] Minimum bottom depth in meter within this subinterval.
  • MaxBottomDepth - [m] Maximum bottom depth in meter within this subinterval.
  • Threshold - [dB] LSSS computes integrated echo level (sA) from volume backscattering (sv) coefficients by performing integration vertically and averaging horizontally. sV coefficients are only included in the computations if their value exceeds a certain threshold. The threshold is identical to the lower boundary of the color scale as set in the color scale field of the echogram view. The Threshold parameter contains the threshold in dB that was used when interpreting this data.
  • BubbleCorrection - [-] Small air bubbles sometimes attenuate the echosounder signal, and a multiplication factor is available from the Store Interpretation dialogue for manually boosting the signal strength. Both pelagic and bottom channel data are affected by this boosting mechanism. The BubbleCorrection parameter contains the multiplication factor value that was used when interpreting this data.
  • ChannelThickness - [m] Channel thickness in meters.
  • UpperDepth - [m] Upper depth boundary in meters where acoustic data of specified ScatterType exist. UpperDepth is the least depth below sea surface for all pings in the current subinterval (see Duration and DistanceInterval), i.e. UpperDepth = MIN(UpperDepthping(i), ..., UpperDepthping(i+n)). For pelagic channels (i.e. that are referenced to the sea surface), UpperDepth is positive. Bottom channels are referred to detected (coordinated) bottom and are positive downwards, i.e. UpperDepth is negative.
  • LowerDepth - [m] Lower depth boundary in meters where acoustic data of specified ScatterType exist. LowerDepth is the largest depth below sea surface for all pings in the current subinterval (see Duration and DistanceInterval), i.e. LowerDepth = MAX(LowerDepthping(i), ..., LowerDepthping(i+n)). For pelagic channels (ScatterType = "Echogram Pelagic" or "School Pelagic"), LowerDepth is positive. Bottom channels are referred to detected (coordinated) bottom and are positive downwards.
  • SA - [m2/nmi2] This parameter (sA) contains the sum of the interpreted sA values for all the acoustic categories for all the channels in the column. The parameter has dimension square meter per square nautical mile.
  • Quality - {1;2;3} User assigned quality code of for the current interpretation, as defined in the Specify Quality dialogue following the Store Interpretation procedure. The quality code is used to express how confident the user is regarding the acoustic category interpretation.
    1 = best quality, the acoustic category can be separated exclusively by means of the acoustic measurements.
    2 = second best, the acoustic category can be partly separated by the acoustic measurements, but must be supported by biological samples.
    3 = low quality, the acoustic category are completely mixed, and can only be separated by means of biological samples.
  • PctSA - [%] This parameter expresses in percentage the interpreted sA value (above) divided by the total sA in the entire column.
  • UpperInterpretationDepth - [m] Upper depth where the acoustic data are scrutinized and stored. UpperInterpretationDepth >= UpperDepth. For pelagic channels (i.e. that are referenced to the sea surface; ScatterType = "Echogram Pelagic or "School Pelagic"), UpperInterpretationDepth is positive. For bottom channels (i.e. that are referenced to the detected bottom (i.e. coordinated bottom); ScatterType= "Echogram Bottom" or "School Bottom"), UpperInterpretationDepth is negative. Bottom channels are restricted by the extent of the (visible) bottom window, which typically by default shows 10 m above bottom. See also UpperDepth.
  • LowerInterpretationDepth - [m] Lower depth where the acoustic data are scrutinized and stored. LowerInterpretationDepth <= LowerDepth. For ScatterType = "Echogram Bottom" (and "School Bottom"), LowerInterpretationDepth is typically restricted by the lower integration line, which is -0.5, i.e. 0.5 m above detected bottom (i.e. coordinated bottom).
  • BottomActive - {1;0} For a given Object, the flag tells if the bottom was active (= 1) or not (= 0) when the data was scrutinized. The BottomActive = 1 if the postprocessing system was running in "FULL MODE" (formerly known as "SURFACE MODE") when the data was scrutinized, and BottomActive = 0 if the system was running in "PELAGIC" mode.
