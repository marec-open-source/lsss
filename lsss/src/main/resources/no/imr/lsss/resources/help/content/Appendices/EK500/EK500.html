BEI / EK500

This section applies to EK500 data and Bergen Echo Integrator (BEI) work files. Bergen Integrator 500 (BI500) work files is a subset of BEI work files. The functionality described here can be reached from [Survey configuration - Data files].

Settings

The EK500 settings editor is used for specifying parameters that are not available in the EK500 data. These parameters are used for conversion to EK60 format.

The frequencies in the EK500 data are substituted by the closest configured frequencies in the EK500 settings if the difference is less than 1 kHz. If, for example, the EK500 data contains a transducer with frequency 37879 Hz and the EK500 settings are specified for 38 kHz, then the EK500 data will appear in LSSS as 38 kHz.

Loading EK500 data

The times of the index records in the *-Ping files (time format YYYYMMDD HHMMSS) are corrected using the corresponding *-Time files (time format HHMMSSXX) if available. *-Time files only exist in the late version of BEI, but not in BI500. This correction follows the following algorithm:

  1. A representative difference between times, tt, on *-Time files and times, tp, on *-Ping files is found by computing Δt = median of tt - tp for the first 100 files for each frequency.
  2. For each *-Ping file the time of an index record, tp, is replaced by tt + tcorr, where tcorr is initially 0. If |(tt + tcorr - tp) - Δt| > 30 seconds then tcorr is set to Δt - (tt - tp).
  3. The corrected index record times are possibly modified to ensure they are not decreasing.

After correction of times, the index records from the different transducers are organized into pings:

  1. The largest group of synchronized transducers is identified. (Two transducers are considered synchronized if the set of corrected times from one transducer overlaps the set of corrected times from the other transducer with more than 80%.)
  2. One ping is created for each time in the union set of all corrected times from the transducers in the identified synchronized group.
  3. The index records for all transducers are assigned to the ping with time nearest, but not after.

The EK500 data contains separate sections of pelagic data and bottom data.

  • If these data segments are disjoint, the bottom data is discarded.
  • The bottom data is used to overwrite the pelagic data.
  • The smallest sample distance is used in the resulting data.

The last index record on a file is often seen to contain erroneous data. Therefore, the last index record is replaced by a copy of the second last. Files with frequency 0 Hz are ignored.

Converting work files

Note that if both work files and snap files are found, the snap files are used.

Only layers for the frequency closest to the configured main frequency are converted, while schools for all frequencies are considered in the conversion. The conversion algorithm scans through all frequencies, and converts schools that are not overlapping with already converted schools (LSSS does not accept new schools that overlap with existing schools).

The BEI species are converted to LSSS species according to the mapping given in the file SpeciesMap.txt, which can be found in the folder lsss/data/ek500 in the LSSS installation directory. The species numbers [1, 31] and [41, 52] (for Norway: [1, 69]) are assumed to have the identity mapping unless reassigned in this file. If a mapping is not found during the conversion, the interpretation is set to the configured default species.

The conversion of layers and schools uses the following procedure:

  1. If the bottom data window was active in BEI, then a layer is created ranging from the bottom layer boundary up to the extent of the bottom data window. Only one layer is created from the bottom data window.
  2. The layers in the pelagic data window are created above the layer from the bottom data window. The lowest layer extends down to the extent of the pelagic data window. If the pelagic and bottom channels overlap, then the layer from the bottom data window is used and the pelagic layers are truncated. If there is a gap between the pelagic data window and the bottom data window, then a layer with no species assignments is created.
  3. Schools in the pelagic data window are created, but only in the region covered by the layers created from the pelagic data window. If a school extends into the region covered by the bottom data window, then the school is truncated.
  4. No schools are expected within the extent of the bottom data window.
