Examples using KORONA

This section describes possible use cases for preprocessing in KORONA. The data flows through the KORONA modules in a sequence described in the module setup, and some processing modules use the content of a reference file as illustrated in the figure below. Several modules may use the same reference file. Note that the sequence of the processing modules may affect the result. For example, noise removal (NoiseRemovalModule) needs to be done after noise quantification (NoiseQuantificationModule). Further, the best data used to quantify noise is picked somewhat "below" the detected bottom (really: some time after bottom echo), so the Bottom detection module should be used before the NoiseQuantificationModule.

The processing modules can be grouped into 6 classes:

  1. Data improvement modules. These manipulate data, but the data-format and file-size remain unchanged.
  2. Data reduction modules. These remove or compress the data, but do not add information in the form of new data-telegrams.
  3. Echo-trace detection modules. These detect the extent of e.g. a school or a single-fish track, and calculate parameters that characterize the echo-trace and pass this information as new data-telegrams in the data in addition to those defined by the data-file format *.raw.
  4. Identification of acoustic scattering classes by means of an acoustic feature library or by scattering models. The information is passed as new data-telegrams in the data.
  5. Generation and removal of data-channels through mathematical operators.
  6. Modules for visualizing intermediate results, e.g. echogram between any two processing modules.
