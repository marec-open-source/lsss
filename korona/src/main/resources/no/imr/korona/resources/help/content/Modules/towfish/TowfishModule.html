Towfish merging module

Merges towfish data with the main echosounder data.

For each ping in the input data, the module searches for a corresponding ping in the towfish data. For a corresponding towfish ping to be found, the following criteria must be met:

  • A towfish sensor data file folder must be specified
  • There must exist towfish sensor data, and the time of the input ping must correspond to sensor data for that time. The sensor data must be on one of the formats specified in sensor data section
  • There must exist towfish raw data for the towfish corresponding to the input ping time

If a towfish ping is found, the data from the towfish ping is merged with the input data.

The module attempts to use the data for cable length and depth of the towfish (from the sensor data) to find a matching towfish ping for a given input ping. To do this, there must be a relationship between the cable length L and the towfish depth, D on one hand and the distance behind the ship on the other hand. Two types of functions are available:

  • Pythagoras: The distance behind the ship is given as sqrt(L2 - D2)
  • Straight down: The distance behind the ship is 0

Parameters

  • Active: If the module is not active, then all datagrams pass unaltered through it.
  • Towfish blind zone: The blind zone of the towfish vessel. The samples in the blind zone are excluded when merging the towfish data with input data.
  • Time to add to the towfish echosounder data: If there is a known time offset between the towfish echosounder data and the towfish sensor data and the ship mounted echosounder data, the offset can be entered here.
  • Distance behind function: The relationship between the cable length and towfish depth on the one side and the distance behind the ship on the other side.

Sensor data

Currently, three types of towfish sensor data can be read by the towfish module. The expected format is decided by the name of the directory where the sensor data file is found. The acoustic data from the towfish should be placed in the configured Towfish directory, and the sensor data directory should be a subdirectory to the Towfish directory.

The following naming conventions for the subdirectory are used:

  • Consys: Consys-metadata
  • Messor: Messor-metadata
  • Must: Must-metadata

The formats and the sensor data directory name are explained below.

Telegram based data

Sensor data directory name: Consys-metadata. In this format, the data comes as telegrams in a flat text file. Each line in the file starts with the time and date in the following format:

dd.MM.yyyy,HH:mm:ss

The relevant telegrams are:

  • Pressure: Pressure = 110.300 dB Temperature = 10.2 dgr C, where pressure is in decibars and temperature is in degrees Celsius
  • Cable length: L=102.9m S=13.4m/m, where L is cable length [meters] and S is winch speed [meters/minute]
  • Ship vessel log: $EKDEA,D2,19360507,1823.9,6,1,0,*5c, where the third parameter is the time/data and the fourth parameter is the vessel log in nmi

Line-based data

In this format, each line is a complete set of parameters for the towfish. The first line should be headers giving the name of the columns. For all following lines, each line starts with the time and date, and contains vessel log and depth. All numbers use '.' as decimal character. There are currently two variants of line-based data available based on sensor data files from two different tow-bodies (MUST and MESSOR).

Sensor data directory name: Messor-metadata. The relevant columns of MESSOR separated by tab are:

  • Column 0 - Date and time: format ddMMyyyyHHmmss
  • Column tag "EK_Log-Dist" - Vessel log: The vessel log in nmi
  • Column tag "CTD_Depth(m)" - towfish depth: The depth of the towfish in meters

Sensor data directory name: Must-metadata. The relevant columns of MUST separated by " , " (space-comma-space) are:

  • Column 0 - Date and time: format yyyyMMddHHmmssSS
  • Column tag "ShipER60VesselLog" - Vessel log: The vessel log in nmi
  • Column tag "CTDDepth" - towfish depth: The depth of the towfish in meters
