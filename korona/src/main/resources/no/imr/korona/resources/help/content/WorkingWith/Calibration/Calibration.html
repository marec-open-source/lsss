Calibration

Calibration of data is done if a file named "calibration.xml" exists in the same directory as the raw data files.

Simple example

<?xml version="1.0" encoding="UTF-8"?>
<calibration>
   <default g="26.5" SA="64:-0.49, 128:-0.71, 256:-0.58, 512:-0.77,  1024:-0.66, 2048:-0.42, 4096:-0.35, 8192:-0.35"/>
   <case channel="1" kHz="18" g="22.4" SA="512:-0.59, 1024:-0.65, 2048:-0.45, 4096:-0.4,  8192:-0.35"/>
   <case channel="2" kHz="38" g="26.5" SA="256:-0.58, 512:-0.77,  1024:-0.66, 2048:-0.42, 4096:-0.35"/>
   <case channel="3" kHz="70" g="27.0" SA="128:-0.88, 256:-0.82,  512:-0.53,  1024:-0.39, 2048:-0.41"/>
   <case channel="4" kHz="120" g="27.0" SA="64:-0.49, 128:-0.71,  256:-0.66,  512:-0.41,  1024:-0.32"/>
   <case channel="5" kHz="200" g="27.0" SA="64:-0.66, 128:-0.76,  256:-0.38,  512:-0.32,  1024:-0.29"/>
   <case channel="6" kHz="333" g="27.0" SA="64:-0.50, 128:-0.70,  256:-0.35,  512:-0.30,  1024:-0.30"/>
</calibration>

If the default element is present, then it will apply to all channels without a separate case element. If a separate case element is specified for a channel, then none of the information from the default element is used.

At least one of the attributes 'id' and 'channel' must be specified. All other attributes are optional.

If an actual transducer configuration in a data file for a specified 'id' or 'channel' does not match all the values specified for 'id', 'channel' and 'kHz' then a warning is given and the calibration is not applied.

Attribute Unit Description
id The channel id
channel The channel number
kHz kHz The frequency in kHz
g dB New value for gain
SA μs:dB New values of the sa correction table given as a comma separated list mapping from pulse length (in microseconds) to sa correction
abs dB/m Absorption coefficient
sound m/s Sound velocity
equivalentBeamAngle dB Equivalent beam angle
beamWidthAlong deg Beam width alongship
beamWidthAthwart deg Beam width athwartship
angleOffsetAlong deg Angle offset alongship
angleOffsetAthwart deg Angle offset athwartship

Example with multiple time intervals

<?xml version="1.0" encoding="UTF-8"?>
<calibration>
   <calibration begin="2010-01-01T12:00:00Z" end="2010-02-01T12:00:00Z">
      <case channel="1" kHz="18" g="22.4" SA="512:-0.59, 1024:-0.65, 2048:-0.45, 4096:-0.4,  8192:-0.35"/>
      <case channel="2" kHz="38" g="26.5" SA="256:-0.58, 512:-0.77,  1024:-0.66, 2048:-0.42, 4096:-0.35"/>
   </calibration>
   <calibration begin="2010-03-01T12:00:00Z" end="2010-04-01T12:00:00Z">
      <case channel="1" kHz="18" g="22.4" SA="512:-0.59, 1024:-0.65, 2048:-0.45, 4096:-0.4,  8192:-0.35"/>
      <case channel="2" kHz="38" g="26.5" SA="256:-0.58, 512:-0.77,  1024:-0.66, 2048:-0.42, 4096:-0.35"/>
   </calibration>
</calibration>

The calibration element can have multiple nested calibration elements specifying begin and end times. The times are specified in UTC using the format YYYY-MM-DDThh:mm:ssZ in accordance with ISO 8601.

If the begin time is omitted, it is taken to mean since the beginning of time.
If the end time is omitted, it is taken to mean to the end of time.

NB! Note that the calibration element matching the time of the CON0 datagram will be used for the entire data file. This means that even if the time of a ping matches a different calibration element, then the calibration element matching the time of CON0 datagram will be used.

NB! Note that if the time matches the interval of a nested calibration element, then only that element is used. Specifically, top level default and case elements are not merged with those of a nested element. In the example below, only channel 2 will be modified between 2010-01-01T12:00:00Z and 2010-02-01T12:00:00Z, as the top level default and case elements do not apply. 

<?xml version="1.0" encoding="UTF-8"?>
<calibration>
   <default g="26.5" SA="64:-0.49, 128:-0.71, 256:-0.58, 512:-0.77,  1024:-0.66, 2048:-0.42, 4096:-0.35, 8192:-0.35"/>
   <case channel="1" kHz="18" g="22.4" SA="512:-0.59, 1024:-0.65, 2048:-0.45, 4096:-0.4,  8192:-0.35"/>
   <calibration begin="2010-01-01T12:00:00Z" end="2010-02-01T12:00:00Z">
      <case channel="2" kHz="38" g="26.5" SA="256:-0.58, 512:-0.77,  1024:-0.66, 2048:-0.42, 4096:-0.35"/>
   </calibration>
</calibration>

In fact, the above example is equivalent to 

<?xml version="1.0" encoding="UTF-8"?>
<calibration>
   <calibration>
      <default g="26.5" SA="64:-0.49, 128:-0.71, 256:-0.58, 512:-0.77,  1024:-0.66, 2048:-0.42, 4096:-0.35, 8192:-0.35"/>
      <case channel="1" kHz="18" g="22.4" SA="512:-0.59, 1024:-0.65, 2048:-0.45, 4096:-0.4,  8192:-0.35"/>
   </calibration>
   <calibration begin="2010-01-01T12:00:00Z" end="2010-02-01T12:00:00Z">
      <case channel="2" kHz="38" g="26.5" SA="256:-0.58, 512:-0.77,  1024:-0.66, 2048:-0.42, 4096:-0.35"/>
   </calibration>
</calibration>

EK80 calibration

An EK80 calibration file can be used by referring to it from "calibration.xml": 

<?xml version="1.0" encoding="UTF-8"?>
<calibration refEK80="TrList_calibration.xml"/>

The value of the 'refEK80' attribute is the path to the EK80 calibration file. The path can be absolute or relative to the directory containing "calibration.xml".

If an EK80 calibration file is specified, then only that file is used. Any content within the 'calibration' element is ignored.

The channels in the EK80 calibration file are identified by transducer name and serial number. The calibration is applied to channels in the actual data files only for matching transducer name and serial number.
