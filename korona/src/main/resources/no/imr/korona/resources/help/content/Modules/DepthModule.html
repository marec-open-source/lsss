Bottom detection module

Module for detecting bottom depth.

Three algorithms are available:

  • EK500: An algorithm similar to the one used in the EK500 system.
  • Gradient: Finds some bottom candidates and gives them points according to signal strength, distance from transducer, and distance from previously found bottom.
  • Threshold: Returns the depth where for the first time the signal strength is above a pre-specified threshold.

Finding a channel-dependent bottom depth

The algorithms above find one bottom depth per ping common for all channels. The module then also finds a bottom depth for each of the channels according to the algorithm below:

For all channels:

  1. Find the sample number corresponding to the detected bottom depth.
  2. Create a moving average filter with a length of about 0.2 m. If the sample distance is above 0.1 m, a moving average filter of length 1 is used.
  3. From the sample number found in 1., find the actual peak by using the moving average filter, and moving maximally 10 m in each direction.
  4. Back-stepping: From the peak value step in the direction of the transducer until the value (according to the moving average filter) is less than Min depth value fraction of the peak value found in 3. The depth of this value is the channel-dependent bottom depth.

Coordinated bottom

The following algorithm is used for finding the coordinated bottom:

  1. Use the bottom depths detected on all frequencies between Minimum kHz and Maximum kHz, but excluding Do not use kHz.
  2. Find the maximum depth.
  3. Clamp the remaining depths to be no less than Min depth limit above than the maximum depth.
  4. Reject the depths less than Minimum depth threshold factor times the maximum depth.
  5. The coordinated depth is computed from the remaining depths:
    1. If the depth for the Preferred kHz is accepted, then it is used.
    2. Otherwise, the smallest of the remaining depths is used.

The bottom datagrams, BOT0, that may accompany the raw data files are used to detect the case that no bottom can be found. If the accompanied bottom datagrams exist and have detected zero-depth for all channels, this is used as an indication that there is no detectable bottom, and detection algorithms will not be called unless Always detect bottom is selected.

The coordinated bottom is used in other preprocessing modules.

This module re-detects the bottom depth every time it is used in the processing setup. Only the coordinated bottom depth is used in the other preprocessing modules. The channel-dependent bottom depths are written to a separate file which can be read and used by LSSS.

New datagrams

  • Depth datagrams, Dep0Datagram. These datagrams (one per ping) represent the coordinated depth.
  • Bottom datagrams, Bot0Datagram. These datagrams (one per ping) represent the channel-dependent depths (contains one depth per channel).

Parameters

  • Active: If the module is not active, then all datagrams pass unaltered through it.
  • Algorithm: Specifies the algorithm to be used in the bottom calculation.
    Allowed values: { EK500, Gradient, Threshold }
  • Min depth limit: Specifies the maximal distance above bottom accepted as the minimal bottom distance.
  • Min depth value fraction = "Backstep": For the minimal bottom calculation. The module backsteps from the depth maximal bottom echo strength, until the echo strength is less than this fraction of the maximal bottom echo strength.
  • Signal strength threshold: The detected bottom must have signal strength larger than this value.
  • Minimum depth threshold factor: Shallowest acceptable depth relative to max depth.
  • Max range factor: Factor to multiply with given transducer ranges for ranges used in depth detection.
  • Always detect bottom: Always try to detect bottom even if echosounder has zero bottom at all frequencies.
  • Keep bottom deeper than data Keep echosounder bottom if it is deeper than available data.
  • Minimum bottom depth: The detected bottom must be minimum this value.
  • Maximum bottom depth: The detected bottom must be maximum this value.

Parameters for coordinated bottom

  • Preferred kHz: Preferred frequency for finding coordinated bottom.
  • Minimum kHz: Only use channels with at least this frequency.
  • Maximum kHz: Only use channels with at most this frequency.
  • Do not use kHz: Comma-separated list of frequencies to not use.
  • Coordinated bottom offset: Additional offset for coordinated bottom. Aa positive offset means smaller depth.
